## Project: AI/Spec-Driven Book RAG Chatbot Integration

**Context:** The Docusaurus book is already deployed to GitHub Pages. This specification focuses solely on developing and integrating the RAG chatbot (Point 2 of the project brief).

### 1. Data Processing and Indexing

| Spec ID | Requirement | Detail | Key Metric/Tool |
| :--- | :--- | :--- | :--- |
| **DPI.1** | **Source Data** | The input source must be the Markdown/HTML files generated by the Docusaurus build for the published book content. | Docusaurus Build Output Path |
| **DPI.2** | **Chunking Strategy** | Specify the chunking method (e.g., recursive character splitter) including target size and overlap. | Chunk Size (e.g., 512 tokens), Overlap (e.g., 50 tokens) |
| **DPI.3** | **Embedding Model** | Define the specific embedding model to be used for generating vector representations. | Model Name (e.g. sentence-transformers/all-MiniLM-L6-v2, OpenAI `text-embedding-3-small`) |
| **DPI.4** | **Vector Database (Qdrant)** | Define the Qdrant Cloud Free Tier configuration. | Collection Name, Vector Dimension (must match embedding model output) |
| **DPI.5** | **Test** | Ensure all the book content should be uploaded on qdrant

### 2. RAG Backend Service (FastAPI)

| Spec ID | Requirement | Detail | Key Metric/Tool |
| :--- | :--- | :--- | :--- |
| **RBS.1** | **Framework** | The backend must be built using FastAPI. | Python 3.10+, FastAPI |
| **RBS.2** | **Chat Endpoint** | Implement a primary endpoint for answering general user questions. | `POST /api/chat`, input: `question` (string) |
| **RBS.3** | **Contextual Chat Endpoint** | Implement an endpoint that prioritizes user-selected text as context alongside vector retrieval. | `POST /api/selection-chat`, input: `question` (string), `selected_text` (string) |
| **RBS.4** | **Retrieval Logic** | Define the search parameter for Qdrant (e.g., top-k, score threshold). | `k` value (e.g., 5), Similarity metric (Cosine) |
| **RBS.5** | **LLM Orchestration** | The service must use the OpenAI Agents/ChatKit SDKs to manage the RAG flow and LLM interaction. | OpenAI Agents/ChatKit Python SDK |
| **RBS.6** | **Agent Prompt (Guardrail)** | The agent's system prompt must enforce that the response is generated *strictly* using the retrieved context from the book, and to state clearly if the answer is not found in the book. | Agent System Prompt (Text) |

### 3. Frontend Integration (Docusaurus/React)

| Spec ID | Requirement | Detail | Key Metric/Tool |
| :--- | :--- | :--- | :--- |
| **FES.1** | **UI Component** | The chatbot must be integrated as an embeddable component within the Docusaurus site. | React Component Name (e.g., `RAGChatbot.js`) |
| **FES.2** | **API Communication** | The frontend must communicate securely with the deployed FastAPI backend. | Base URL of Deployed FastAPI |
| **FES.3** | **Text Selection Capture** | Implement JavaScript logic to capture any text selected by the user globally across the book pages. | `window.getSelection()` logic |
| **FES.4** | **Contextual Chat Trigger** | If text is selected, the chat interface must indicate that the next question will use the selected text as *priority context* and send it via the **RBS.3** endpoint. | UI State/Flag for 'Contextual Mode' |
| **FES.5** | **SDK Usage** | The frontend should utilize the ChatKit.js client-side library for managing chat state and communication, where feasible. | ChatKit.js Client-Side SDK |

### 4.  Testing and Deployment

| Spec ID | Requirement | Detail | Key Metric/Tool |
| :--- | :--- | :--- | :--- |
| **DEP.1** | **Testing** | Test the chatbot is working right with the user queries be answered using FASTAPI, OPENAI Agents SDK and Qdrant logic implemented in backend.
| **DEP.2** | **Backend Deployment** | Specify the target platform for the FastAPI service. | Target Platform (e.g., Render, Fly.io, etc.) |
| **DEP.3** | **CORS** | The FastAPI service must be configured with appropriate CORS headers to allow calls from the Docusaurus deployment on GitHub Pages. | Allowed Origin (GitHub Pages URL) |

**End of Spec**
